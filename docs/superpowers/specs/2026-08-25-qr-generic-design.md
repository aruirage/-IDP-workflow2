# QR 通用读取方案设计

日期：2026-08-25  
状态：待评审  
范围：第二期 workflow-ph2 · QR 读取能力

---

## 1. 背景与目标

### 1.1 问题

- 现有原型与 PRD 以 LIAJ045 诊断书六码为默认场景，字段映射写死 QR1～QR6，过于定制。
- 配置端是否需要维护 QR 物理位置存疑；扫描旋转/裁剪可能导致固定位置方案失效。
- QR 要確認 是否独立待办类型不明确。

### 1.2 目标

- 用**通用多 QR 源模型**覆盖单 QR 与多 QR（LIAJ045 仅为 preset）。
- **配置端不定坐标**；引擎按内容签名归类 QR。
- **有 QR 读取节点 → 优先 QR，QR 失败/空缺 → OCR 兜底**；无节点 → 纯 OCR。
- **QR 要確認 并入 OCR 抽出确认**，确认页仅做增量展示。

### 1.3 非目标

- 配置端读区框选、像素坐标维护。
- 新增「QR 确认」待办类型。
- 脱敏专用待办（沿用 P1）。

## 2. 配置分层

### 2.1 推荐方案：Step2 读取模式切换 + Step3 纯处理规则

| 层级 | 位置 | 职责 |
| ---- | ---- | ---- |
| OCR 字段读取 | 账票类型 **Step2 · OCR 模式** | 字段定义、prompt、脱敏等（沿用 P1） |
| QR 字段读取 | 账票类型 **Step2 · QR 模式** | QR 源目录 + 字段 QR 映射（按需） |
| OCR 后处理 / 范围 | 账票类型 **Step3 処理ルール** | 処理ルール、正常值范围、AI マッチング（**无 QR 列**） |
| 执行开关 | 工作流 QR 读取节点 | 按账票类型 ON/OFF |

**向导保持五步**，不新增独立 QR Step。Step2 / Step3 / Step5 共用 **テキスト読取 | テーブル情報読取** 双 Tab，字段行对齐。

```
Step1 分类+模板上传 → Step2 AI读取[OCR|QR] → Step3 処理ルール → Step4 图像 → Step5 效果测试
```

#### Step2 布局

```
Step2  AI读取
┌─ 读取模式（段切换）──────────────────────────────┐
│   [ OCR读取 ]  [ QR读取 ]     ← 同一字段表两种视图 │
└──────────────────────────────────────────────────┘
  [ テキスト読取 ]  [ テーブル情報読取 ]

  OCR 模式列：項目名、类型、prompt、正解サンプル、必須、マスク…
  QR  模式列：項目名、QR、QR源、抽出方式、区切り、分割索引、解析样例
```

- **同一批字段行**：OCR / QR 切换只换列，不换 Tab、不换步。
- **字段清单共用**：項目名与表格列在两种模式间共享；先通过 OCR 模式惯用流程建好字段清单，再切 QR 模式配映射。
- **样张**：QR 解析复用 **Step1 template**（左侧预览共享），Step2 不上传。

#### Step2 配置流：OCR 与 QR 对照（同一习惯）

两种模式遵循**相同三步节奏**，仅 AI 产出不同：

| 步骤 | OCR 模式（沿用 P1） | QR 模式（本期） |
| ---- | ------------------- | --------------- |
| 1. 导出 template | 导出字段/表格清单模板（Excel 等） | **同一 template**；不要求单独 QR 模板 |
| 2. 填写清单 | 填 `項目名`、表格名与列键名 | **同一清单**；与 OCR 共用，无需重复填 |
| 3. AI 自动生成 | 点 **AI自動生成** → 生成各字段 `プロンプト` + `正解サンプル` | 点 **AI自動生成**（或「从样张解析 QR」）→ 基于 Step1 样张 + 已有字段清单，生成 `qrSources` + 各字段 QR 映射 + **`解析样例`** |

**QR 模式第 3 步产出（对标 OCR 的 prompt / 正解サンプル）：**

| OCR 列 | QR 等价列 | 说明 |
| ------ | --------- | ---- |
| プロンプト | QR源 + 抽出方式 + 区切り + 分割索引 | 怎么从 QR 取值 |
| 正解サンプル | **解析样例** | 从 Step1 样张 QR 解析出的预期值，供 Step5 试读对照 |

QR 工具区（QR 模式 Tab 栏旁，与 OCR 的 ⚙/▣ 同级）：

```
[ 导出 template ]  [ AI自動生成 ]     ← 与 OCR 模式同一位置、同一习惯
```

- **导出 template**：与 OCR 相同文件；导入后刷新 `項目名` / 表格列（两种模式同步）。
- **AI自動生成（QR）**：扫描 Step1 样张 → 更新 QR 源目录 → 为已有字段行写入映射与解析样例；默认不覆盖已手工编辑行。
- 行业协议（如 LIAJ045）：解析时自动识别并增强建议，无单独 preset 按钮。

**推荐顺序：**

```
Step1 上传样张
  → Step2 OCR 模式：导出 template → 填字段/表格 → AI自動生成（prompt + 正解）
  → 切 QR 模式：AI自動生成（QR 源 + 映射 + 解析样例）→ 手工微调
  → Step3 処理ルール …
```

不用 QR 的账票：只走 OCR 三步，不切 QR 模式即可。

#### 跳过 QR（按需）

| 状态 | 条件 | 表现 |
| ---- | ---- | ---- |
| **未配置 QR** | 从未切到 QR 模式，或 QR 模式未保存任何源/映射 | 默认；Step2 步标无 QR 标记 |
| **已配置 QR** | 至少 1 个 qrSource 且 ≥1 字段有 qrMapping | Step2 步标「QR 已配置」 |
| **发布校验** | 工作流 QR 节点 ON + 该账票未配置 QR | 设置检查阻断 |

不设单独「跳过开关」：不用 QR 就不切 QR 模式即可。

与 OCR 抽出、个人信息脱敏一致：规则在账票类型 Step2，节点管本案跑不跑。

### 2.2 Step2 · QR 模式（与 OCR 同节奏）

字段清单建立方式与 OCR **完全一致**（导出 template → 填写 → AI）。QR 模式仅替换第 3 步 AI 产出物。

#### AI自動生成（QR）— 单次完成

对 **Step1 template** + **Step2 已有字段/表格清单**：

1. 全页 QR 扫描 → 生成 / 更新 `qrSources[]`
2. 为每个 `項目名` / 表格列建议 `qrMapping`（源、抽取、区切り、索引）
3. 写入 **解析样例**（对标 OCR `正解サンプル`）
4. 配置人审阅；默认不覆盖已手工编辑行

命中 LIAJ045 等已知协议时，引擎增强映射建议；UI 提示「已识别行业标准结构」。

| 条件 | 行为 |
| ---- | ---- |
| 字段清单为空 | AI 禁用；提示先导出 template 填写或 OCR 模式添加字段 |
| Step1 无 template | AI 禁用；提示回 Step1 上传 |
| 样张无 QR | 生成 0 源；提示确认样张或仅用 OCR 模式 |
| Step1 换 template | 提示「样张已变更，建议重新 AI 生成」 |

| 辅助能力 | 说明 |
| ---- | ---- |
| QR 源目录 | AI 生成后可手工增删改 SRC、matchRule |
| 批量选择字段 | 多选 → 统一指定 QR 源、抽取方式 |
| 分段预览 | 点选 split 段填入 segmentIndex |

### 2.3 账票类型 · QR 源目录

```
qrSources[]   // 1～N
├── id          // 如 SRC-1、SRC-2（不用 QR1 等行业专用名）
├── label       // 如「患者基本」「发行信息」
├── sortOrder   // 展示排序
└── matchRule?  // 可选，preset 导入时带入
    ├── type: prefix | regex | segmentCount | presetProtocol
    └── value
```

- 普通单 QR 账票：解析后通常 `qrSources` 长度 = 1，`matchRule` 可省略。
- LIAJ045 等：样张解析时内容命中 `presetProtocol` 则自动建议 6 源 + 默认映射，无单独 preset 按钮。

### 2.4 账票类型 · 字段 QR 映射

```
qrMapping?
├── enabled         // 该字段是否从 QR 取值
├── qrSourceId      // 指向 qrSources[].id
├── extractMethod   // 全文 | 分隔符分割
├── delimiter       // 分割符，如 $
├── segmentIndex    // 分割后第几段（0 起）
└── parsedSample?   // 解析样例（对标 OCR 正解サンプル，Step5 试读对照）
```

字段 QR 开关：表示「该字段是否配置了 QR 取值规则」，不是「本案是否扫描」。

### 2.5 工作流 · QR 读取节点

```
perDocTypeEnabled: Record<docTypeId, boolean>
```

- 仅 ON/OFF，不含字段映射。
- 设置检查：画布含 QR 读取节点时，至少一个关联账票 ON。

## 3. 运行时优先级（核心）

### 3.1 决策树

```
画布是否含 QR 读取节点？
├─ 否 → 全字段走 OCR 抽出（与 P1 相同）
└─ 是 → 该账票类型节点 ON？
    ├─ 否 → 该账票 skip QR 段，全字段 OCR
    └─ 是 → QR 优先链：
        ① AI 前处理（纠偏/旋转）
        ② 全页 QR 扫描 + 内容归类 → qrSources
        ③ 按字段 qrMapping 写值
        ④ QR 为空 / 源未检出 / 归类歧义 / 要確認
           → 该字段 OCR 兜底
        ⑤ OCR 后处理 + 正常值范围校验
        ⑥ reviewRequired 字段 → OCR 抽出确认待办
```

### 3.2 QR 优先 + OCR 兜底规则

| 场景 | QR 段 | OCR 段 | 取值来源标记 |
| ---- | ----- | ------ | ------------ |
| QR 成功写值且无需确认 | 写值 | 跳过该字段识别 | QR |
| QR 未检出该源 | — | 识别该字段 | QR→OCR兜底 |
| QR 值歧义 / 要確認 | 写候选值 + reviewRequired | 并行 OCR 作对照 | QR（待确认）→ 确认页可改 |
| QR 节点 OFF | skip | 全字段 OCR | OCR |
| 无 QR 节点 | — | 全字段 OCR | OCR |
| 字段 qrMapping.enabled=false | — | OCR | OCR |

节点级 `qrReadStatus`：
- 该账票 OFF 或无 qrSources → success（skip）
- 至少一个源成功或已 OCR 兜底继续 → success
- Agent 解码整体失败且无法继续 → failed（通知 + 案件异常，不单独开 QR 待办）

字段级确认统一进 **OCR 抽出确认**，原因标签含 `QR要確認`。

## 4. QR 识别：不定死位置

### 4.1 配置端禁止

- 读区框选、x/y/宽高、「QR1 必须在左上角」类配置。

### 4.2 引擎识别策略（优先级）

1. **内容签名匹配**：按 `matchRule` 将解码串归类到 `qrSourceId`。
2. **单码简化**：页上仅 1 个 QR 且账票仅 1 个源 → 直接映射。
3. **行业 preset 协议**：`presetProtocol=LIAJ045` 时在引擎内用 payload 结构规则辅助（不作唯一依据）。
4. **歧义/缺码**：缺码 → OCR 兜底；歧义 → 进 OCR 抽出确认，QR/OCR 并列可改。

旋转/尺寸问题由 AI 前处理归一；缺码不阻断整案。

## 5. 确认页（OCR 抽出确认 · 增量）

### 5.1 待办类型

不新增枚举。QR 要確認、低置信、范围越界等统一进 **OCR 抽出确认**。

### 5.2 无 QR 节点

确认页与第一期完全相同。

### 5.3 有 QR 节点 · 字段行增量

| 增量项 | 说明 |
| ------ | ---- |
| 取值来源 | QR / OCR / QR→OCR兜底 |
| 失败原因标签 | 含 QR要確認 |
| QR 源 | 如 SRC-1 · 患者基本 |
| QR 候选 / OCR 对照 | 歧义或要確認时并列展示 |
| QR 原始片段 | 可折叠 |
| 文件级 QR 摘要 | 如「已识别 4/6 源；SRC-3 未检出→OCR兜底」 |

**字段值可编辑**；歧义场景经办选定或手改后办结。

## 6. 与现有 PRD 的差异（需同步）

| 现 PRD | 本设计 |
| ------ | ------ |
| QR 列挤在 Step3 処理ルール表 | Step2 **OCR/QR 模式切换**；Step3 仅后处理 |
| QR 番号 QR1～QR6 | 通用 qrSourceId（SRC-n） |
| LIAJ045 硬编码 | 样张解析时自动识别协议并建议映射 |
| 独立 QR Step / 六步向导 | **五步不变** |
| QR 要確認 | 并入 OCR 抽出确认，可编辑 |

## 7. 异常与边界

| 场景 | 处理 |
| ---- | ---- |
| 未切 QR 模式 / 无映射 | 允许；runtime 全 OCR |
| 工作流 QR ON 但未配 QR | 设置检查阻断 |
| Step1 无 template | 「从样张解析 QR」禁用 |
| 样张无 QR | 解析 0 条；提示换样张或仅用 OCR 模式 |
| 有 QR 节点，物理件无 QR | 全字段 OCR 兜底；qrReadStatus=success |
| 多 QR 源部分缺码 | 缺码源字段 OCR 兜底；摘要展示 |
| QR 与 OCR 值冲突 | 默认 QR 优先；要確認时经办在确认页选定 |
| 字段无 qrMapping | 始终 OCR，不受 QR 节点影响 |
| qrReadStatus=failed | 通知；是否进人工确认沿用 P1 异常策略 |

## 8. 开放项

| ID | 问题 | 建议默认 |
| -- | ---- | -------- |
| P-201 | OCR 是否允许强制覆盖已有 QR 值 | QR 非空则跳过 OCR 识别 |
| P-301 | matchRule 是否对配置端可见可编辑 | preset 导入后可读；高级模式可改 |
| P-302 | QR/OCR 冲突时默认展示哪个 | 确认页并列展示，默认 QR 值可编辑 |

| P-303 | Step1 换 template 后是否自动重跑解析 | 默认不自动；提示「样张已变更，建议重新解析」 |

## 9. 实施影响面（概要）

| 模块 | 变更 |
| ---- | ---- |
| Step2 | OCR/QR 段切换；QR 模式与 OCR 同节奏（导出 template → 填清单 → AI自動生成） |
| Step3 | 移除 QR 列；仅 処理ルール + 范围 |
